# RelayDesk 简历写法

以下内容按项目真实实现编写。不要写未发生的生产指标。

## 项目一句话

独立设计并实现 RelayDesk AI 工单升级工作台，面向 FDE / AI 应用开发场景，将客户问题、日志与内部 Runbook 转化为可追溯的故障判断、安全处置步骤和人工审核后的客户回复。

## 简历 Bullet

- 设计并实现 AI 工单升级工作台 RelayDesk，覆盖工单录入、Runbook 检索、严重级别判断、结构化处置建议、客户回复和人工审批导出完整流程。
- 基于 BM25 构建可解释检索链路，输出来源 ID 与证据片段；实现确定性离线推理和可选 OpenAI Responses API 双路径，Live 输出失败时自动回退。
- 建立 8 条 Golden Case 评测，当前 Runbook Top-1 路由、严重级别、Schema 校验和安全检查均为 8/8，并使用 Node 原生测试覆盖引擎与 API。
- 实现零运行时依赖 Node 全栈应用，加入严格 JSON Schema、引用白名单、请求体限制、限流、安全响应头和静态路径穿越防护。
- 将人工审批设为强制 Handoff Gate，支持风险分级、负责人、客户安全提示和 Markdown 案件简报导出，避免自动发送或自动执行生产变更。

## 面试口述版本

“我做的不是一个聊天框，而是一个 FDE 交付切片。客服把混乱的工单和日志丢进来，系统先检索内部 Runbook，再给出严重级别、证据、可回滚动作和负责人，最后必须由人审核后才能导出或进入工单系统。我重点做了三件事：第一，引用可追溯；第二，模型失败时有确定性回退；第三，用 Golden Case 把检索、分级、Schema 和安全检查做成可回归的评测。下一步我会接真实工单系统和租户级知识库，并加入混合检索。”

## 不要这样写

- 不写“提升客服效率 80%”，项目没有真实用户实验。
- 不写“生产级 RAG”，当前是合成知识库和本地 Demo。
- 不写“全自动处理工单”，产品明确保留人工审批。
